- 質問がある際は`AskUserQuestionTool`を使用してください。ただ、なぜそれを聞きたいのかの背景を詳しく記述する様にしてください。
    - `AskUserQuestionTool` だとコードが読みにくいので、コードを定義する際は先にコードを表示したあとに、`AskUserQuestionTool` を起動してくだっさい。
- 実装が全て終わり次第、`/codex:review` を subagent で実行してください。
- コミットは出来るだけ小さく意味の単位に纏めて作成してください。
- 実装が全て完了した場合は、 /hunk-review スキルを使用して実装した部分を /herdr の別ペインで見せてください。hunkが起動していない場合は自身で起動してください。
- ユーザに相談する際にコードが含まれる場合、対象コードがorigin/main にならば Github のリンクをつけてください。もしない場合は、`bat`コマンドで取得して、プロンプト上に表示してください。その際に vscode などで開けるリンクが別途あると嬉しいです。
- 作成しているPRに対して、GithubにPushする前、レビューアーからのコメント（Botを除く）、後続のブランチが作成されていない場合は、コミット履歴を出来るだけ切れに保ってください。

## herdr関連
- `echo "$HERDR_WORKSPACE_ID"` に値が設定されている場合は、必要に応じて /herdr スキルを使用してください。以下のような場合に利用できます。
    - 並列実装をする場合、herdr で Worktreeを別にして実装をする。
    - ユーザに何かを見せたい場合、同じ workspace の別 pain を起動して表示する。
    - git worktreeを作成する場合。
- 自身が別の herdr の agent から依頼されて起動している場合、実装方針に迷ったら指示役に一旦確認して、それでも解決しなければユーザに聞いてください。
- 作業をする際は指示Agent(Opus)と実行Agent(Sonnet)に分かれて実行をしてください。実行Agentは自身のWorktreeを作成して処理を実施してください。
